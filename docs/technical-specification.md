# Технічна специфікація MVP

[Навігація](README.md)

## Мета

Надати вебінтерфейс для перегляду, фільтрації та експорту агрегованих показників ІТ-освіти з імпортованих наборів, добровільних профілів та підтримуваних відкритих API. Гендерні показники будуються тільки там, де джерело надає відповідні значення.

Документ описує поточну реалізацію, а не обіцянки наступних релізів. Система не встановлює гендер людини та не забезпечує репрезентативності добровільної вибірки.

## Ролі

| Роль          | Доступ                                                               |
| ------------- | -------------------------------------------------------------------- |
| Гість         | Видимі категорії, дашборд, фільтри, експорт, реєстрація/вхід         |
| Користувач    | Можливості гостя та збереження власного профілю зі згодою            |
| Адміністратор | Можливості користувача та керування категоріями, джерелами, наборами |

API перевіряє поточну роль у БД; прихована кнопка не є контролем доступу.

## Вимоги й критерії приймання

| ID    | Вимога             | Спостережуваний результат                                                              |
| ----- | ------------------ | -------------------------------------------------------------------------------------- |
| FR-01 | Розділення джерел  | Чотири вбудовані категорії, seed окремо в «Тестові»                                    |
| FR-02 | Відображення даних | Гендерні метрики для CSV/Eurostat/профілів; кількості вступників для ЄДЕБО             |
| FR-03 | Фільтрація         | Нижні метрики, графіки, розподіл та експорт відповідають UI-фільтрам                   |
| FR-04 | Відповідні виміри  | Eurostat: країна без ЗВО; профілі: рік подання без регіону                             |
| FR-05 | Експорт            | CSV відфільтрованих агрегатів із захистом від формул                                   |
| FR-06 | Авторизація        | JWT після входу/реєстрації; гість не має доступу до захищених маршрутів                |
| FR-07 | Профіль            | Тільки зі згодою; повторне подання оновлює один запис                                  |
| FR-08 | Адміністрування    | Створення категорій/джерел, керування видимістю/активністю                             |
| FR-09 | Імпорт             | Валідація перед відправленням, транзакційний запис/заміна                              |
| FR-10 | Стан імпорту       | Порожня початкова форма, індикатори, блокування submit, очищення після успіху          |
| FR-11 | Інтерфейс          | Дві мови, три режими теми, адаптивні форми та довгі URL                                |
| FR-12 | Приватність        | Приховані категорії не повертають даних; групи профілів менш як 5 осіб не публікуються |

Коло у верхньому блоці зараз показує весь завантажений набір категорії, а не результат UI-фільтрів. Це відоме обмеження FR-03, а не підтверджена фільтрація всіх елементів сторінки.

## Нефункціональні умови

- TypeScript, production build та автоматичні тести мають проходити; форматування узгоджується з Prettier.
- API перевіряє схеми, роль і видимість; SQL використовує параметри.
- CSV: до 20 000 рядків і 10 МіБ UTF-8; JSON-запит також до 10 МіБ. Це різні обмеження розміру.
- Невдала заміна зберігає старий набір через ROLLBACK; успішна фізично видаляє його, не архівує.
- Compose запускає локальну систему однією командою, дані зберігаються в томі.
- Виміряні SLA, production-продуктивність і гранична кількість користувачів не встановлені.

## Поза поточною реалізацією

Універсальні API-конектори, планувальник синхронізації, версіонування наборів, пагінація дашборду, серверна ідемпотентність імпорту, скидання пароля через email, відкликання окремого JWT, UI видалення профілю/відкликання згоди та готовий публічний хостинг.
