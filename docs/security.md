# Налаштування та перевірка безпеки

## Нове локальне встановлення

1. Виконайте `./scripts/setup.ps1`. Скрипт створює `.env` з випадковими секретами БД, JWT та адміністратора. Наявний файл не перезаписується.
2. Виконайте `docker compose up -d --build --wait`.
3. Відкрийте http://127.0.0.1:5173. Email і пароль адміністратора містяться у `.env` (`ADMIN_EMAIL`, `ADMIN_PASSWORD`). Файл ігнорується Git; не публікуйте його.

Старий демопароль `admin123` більше не створюється. За відсутності адміністратора API створює його з налаштувань. На старій БД міграція змінює відомий seed-хеш на новий пароль, зберігаючи обліковий запис і дані. Паролі інших облікових записів автоматично не змінюються. Зміна `ADMIN_PASSWORD` після першого налаштування не є механізмом скидання пароля.

## Оновлення наявного Docker-тома

Зробіть резервну копію БД перед оновленням. Не виконуйте `docker compose down -v`: це видаляє дані.

Зміна `POSTGRES_PASSWORD` в оточенні сама по собі не змінює пароль у вже створеній PostgreSQL. Після створення `.env` виконайте:

```powershell
docker compose up -d db --wait
Get-Content -Raw database/rotate-password.sql | docker compose exec -T db psql -U platform -d gender_platform
docker compose up -d --build --wait
```

SQL отримує новий пароль з оточення контейнера без його виведення. Версійована транзакційна міграція API додає регіон до унікального ключа статистичного спостереження та працює і на старому, і на новому томі. Повторний запуск не повторює міграцію. Секрет JWT змінений — потрібно увійти знову.

## Межі та правила

- Звичайний Compose публікує лише web на loopback `127.0.0.1:5173`. БД доступна лише в мережі Compose. Для локальної розробки з API поза Docker: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db`; порт БД буде доступний лише локально. Налаштуйте `apps/api/.env` із власними DATABASE_URL, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD; не використовуйте старі стандартні паролі.
- JWT: випадковий секрет не менше 32 байтів, HS256, 7 днів; кожний захищений запит перевіряє існування користувача та його поточну роль у БД.
- Пароль: від 8 символів, максимум 72 байти UTF-8 відповідно до bcrypt. Старі паролі понад 72 байти потребують скидання; їхні суфікси вже не приймаються мовчки.
- Вхід: максимум 10 невдалих/одночасних спроб на IP або email за 15 хвилин, `429` і `Retry-After`. Реєстрація: 20 невдалих/одночасних спроб. Лічильники зберігаються в пам’яті одного API; для кількох реплік потрібне спільне сховище. Compose налаштований на один довірений nginx-hop; прямий dev API не довіряє forwarded-заголовкам.
- Імпорт: максимум 2 МіБ JSON і 5000 рядків. Preview має узгоджені межі років/чисел і перевірку дублікатів; JSON може бути більшим за початковий CSV. На перевищення API відповідає `413` або `400`, транзакція зберігає старий набір. Імпортуйте в «Тестові» або власну категорію; live-категорії та профілі формуються окремо.
- Видимість застосовується і до списку категорій, і до даних; прихована/відсутня категорія дає `404`. Невідфільтрований `/dashboard` показує лише видимі імпортовані набори, без підмішування профілів і зовнішніх джерел.
- Зовнішні запити: лише точні HTTPS endpoints ЄДЕБО та Eurostat, без userinfo/довільних шляхів; HTTP-перенаправлення заборонені. Новий адаптер потребує явного розширення переліку дозволених адрес. Тестові HTTP-фікстури підключаються через залежності фабрик тільки в тестах, не через production-конфігурацію.
- Кеші розділені за URL; паралельні завантаження того самого джерела об’єднуються; помилка не кешується. TTL: ЄДЕБО 5 хвилин, Eurostat 12 годин.
- Старий endpoint ЄДЕБО із завершальним `/` локально перетворюється на відомий канонічний endpoint без `/`, який повертає JSON без редиректу. Це фіксоване зіставлення двох дозволених адрес; переходи за HTTP Location залишаються забороненими.
- Eurostat: відображаються лише країни/роки з повними невід’ємними цілими F, M, T та T >= F + M. Пропуски, приховані та неузгоджені спостереження не перетворюються на нулі. Різниця T - F - M означає залишок загальної кількості; сама арифметика не встановлює гендерну ідентичність. Порівняння років може охоплювати різний склад країн.
- Профілі: агрегування за закладом, спеціальністю та роком подання; публікуються тільки групи від 5 учасників. Email, user_id та окремі профілі не передаються. Регіон не збирається. «Інші» об’єднує небінарні відповіді та відмову вказувати стать; це добровільна нерепрезентативна вибірка. Поріг групи зменшує деталізацію, але не є гарантією анонімності чи захистом від усіх атак на статистику.

Для публічного розгортання також потрібні HTTPS, резервне копіювання, власні секрети та окрема політика доступу до інфраструктури. Локальний Compose не є готовою конфігурацією публічного хостингу.

## Повторний аудит

`pnpm --dir audit install --ignore-workspace --ignore-scripts --frozen-lockfile`, потім `./audit/run.ps1`. Потрібний Microsoft Edge. Скрипт використовує окремий проект `gender-security-review` та його том; результати — `audit/api-fixed-results.tap` і `audit/browser-fixed-results.tap`. Контейнери зупиняються після перевірок, том залишається. Старий звіт описує стан до виправлень; його журнали збережені.
