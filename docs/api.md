# HTTP API

[Навігація](README.md) · Реалізація: [маршрути](../apps/api/src/routes/), [схеми](../apps/api/src/schemas.ts).

## Адреса та формат

- Через Docker/nginx: `http://127.0.0.1:5173/api`.
- Прямий API в dev: `http://localhost:3001` (без `/api`).
- Шляхи нижче вказані відносно базової адреси. nginx видаляє префікс `/api`.
- Тіла запитів — JSON з `Content-Type: application/json`, максимум 10 МіБ; multipart upload немає.
- Захищені запити: `Authorization: Bearer <token>`. JWT HS256 діє 7 днів, роль перевіряється за БД.
- Вхідні поля переважно camelCase. DB-сутності у відповідях використовують snake_case; дашборд має власний контракт.
- Приклади UUID нижче синтетичні: підставте реальні ID зі списків.

## Маршрути

| Метод  | Шлях                     | Доступ           | Успішна відповідь                      |
| ------ | ------------------------ | ---------------- | -------------------------------------- |
| GET    | `/health`                | Публічний        | 200 `{ "status": "ok" }`               |
| GET    | `/categories`            | Публічний        | 200 масив видимих категорій            |
| GET    | `/dashboard`             | Публічний        | 200 `{ kind, rows }`                   |
| POST   | `/auth/register`         | Публічний        | 201 `{ token, role }`                  |
| POST   | `/auth/login`            | Публічний        | 200 `{ token, role }`                  |
| PUT    | `/profile/statistics`    | Користувач/адмін | 204 без тіла                           |
| GET    | `/admin/categories`      | Адмін            | 200 усі категорії                      |
| POST   | `/admin/categories`      | Адмін            | 201 створена категорія                 |
| PATCH  | `/admin/categories/:id`  | Адмін            | 200 оновлена категорія                 |
| GET    | `/admin/sources`         | Адмін            | 200 джерела з `category_name`          |
| POST   | `/admin/sources`         | Адмін            | 201 створене джерело                   |
| PATCH  | `/admin/sources/:id`     | Адмін            | 200 оновлене джерело                   |
| DELETE | `/admin/sources/:id`     | Адмін            | 204 без тіла                           |
| GET    | `/admin/datasets`        | Адмін            | 200 метадані наборів і `records_count` |
| POST   | `/admin/datasets/import` | Адмін            | 201 `{ datasetId, imported }`          |
| DELETE | `/admin/datasets/:id`    | Адмін            | 204 без тіла                           |

`/health` перевіряє доступність HTTP-процесу, а не виконує повний тест БД/провайдерів. DELETE із коректним, але відсутнім UUID також повертає 204. Невідомий маршрут може мати стандартну HTML-відповідь Express 404.

## Авторизація та профіль

Обидва auth-маршрути приймають:

```json
{
  "email": "reader@example.com",
  "password": "example-only-change-me"
}
```

Email має бути валідним; пароль — мінімум 8 символів і максимум 72 байти UTF-8. Реєстрація створює роль `user`, навіть якщо клієнт передає іншу роль. Дубль email дає 409. Вхід обмежено 10 невдалими/одночасними спробами на IP або email за 15 хвилин, реєстрацію — 20; успішні спроби знімаються з лічильника.

`PUT /profile/statistics`:

```json
{
  "genderIdentity": "woman",
  "institution": "Приклад університету",
  "specialty": "121 Інженерія програмного забезпечення",
  "educationLevel": "бакалавр",
  "consent": true
}
```

`genderIdentity`: `woman`, `man`, `nonbinary`, `prefer_not_to_say`. Три текстові освітні поля — від 2 символів; `consent` тільки true. Профіль прив'язується до JWT-користувача; `userId` не приймається як спосіб вибрати іншу людину. Оновлення змінює час згоди. GET/DELETE профілю, refresh/logout/password-reset endpoint не реалізовані.

## Дашборд

Необов'язкові query-параметри:

| Параметр      | Значення                                                |
| ------------- | ------------------------------------------------------- |
| `categoryId`  | UUID видимої категорії                                  |
| `year`        | Ціле число 2000–2100                                    |
| `region`      | Непорожній рядок; для Eurostat — назва країни           |
| `institution` | Непорожній рядок; для Eurostat технічно повторює країну |
| `specialty`   | Непорожній рядок                                        |

Фільтри працюють через точну рівність, не пошук підрядка. Без `categoryId` повертаються лише видимі активні **імпортовані** набори, без домішування профілів/зовнішніх API. Немає пагінації та фільтра за рівнем освіти. Прихована або відсутня категорія — 404, навіть для адміністратора на цьому публічному маршруті.

Відповідь гендерного типу:

```json
{
  "kind": "gender-statistics",
  "rows": [
    {
      "year": 2025,
      "region": "Київ",
      "institution": "Приклад університету",
      "specialty": "121 Інженерія програмного забезпечення",
      "women": "120",
      "men": "210",
      "nonbinary": "3",
      "total": "333"
    }
  ]
}
```

`kind` визначає семантику:

- `gender-statistics`: імпортовані агрегати; рівні освіти підсумовано.
- `profile-statistics`: така сама структура, але `region=""`, рік подання, групи від 5 учасників.
- `eurostat-it`: така сама структура, `region` та `institution` — країна; `nonbinary` містить залишок T−F−M, не підтверджену кількість небінарних людей.
- `it-entrants`: `year`, `region`, `institution`, `specialty`, `total`; полів `women`/`men`/`nonbinary` немає.

Лічильники дашборду — рядки з числами. Їхню семантику та обмеження пояснює [методика](data-sources.md).

## Категорії

POST приймає `name` (від 3 символів), `description` (типово порожній), `visible` (типово true). PATCH приймає будь-яку підмножину цих полів. Slug генерується сервером із назви; PATCH назви не змінює slug.

```json
{
  "name": "Навчальні приклади",
  "description": "Синтетичні дані для перевірки",
  "visible": true
}
```

Сутність категорії: `id`, `slug`, `name`, `description`, `visible`; адмінські відповіді додатково містять `created_at`. Повторний slug під час окремого створення дає 409. DELETE категорій немає.

## API-джерела

POST вимагає **рівно одне** з `categoryId` або `category`. Вкладена категорія має `name` і необов'язковий `description`. Якщо її slug вже існує, використовується наявна категорія без оновлення її опису.

```json
{
  "category": {
    "name": "Навчальні приклади",
    "description": "Синтетичні дані"
  },
  "name": "Ручне CSV-джерело",
  "baseUrl": "",
  "importType": "csv",
  "enabled": true
}
```

`name` від 2 символів, `importType` — `csv`/`api`/`manual`, `enabled` типово true. URL необов'язковий або порожній; непорожній має збігатися з allowlist у [описі джерел](data-sources.md). Довільні URL, credentials, query та hash у базовій адресі заборонені.

PATCH підтримує тільки `name`, `baseUrl`, `importType`, `enabled`; категорію не переміщує. Порожній `baseUrl` очищає адресу до порожнього рядка, а не NULL. Відповідь: `id`, `category_id`, `name`, `base_url`, `import_type`, `enabled`, `created_at`; GET додає `category_name`.

Реєстр не є універсальним імпортером. Дашборд використовує два конкретні адаптери з точними назвами вбудованих джерел. Дублікати джерел БД не забороняє.

## Імпорт набору

```json
{
  "categoryId": "11111111-1111-4111-8111-111111111111",
  "title": "Навчальний набір",
  "periodLabel": "2025",
  "records": [
    {
      "institution": "Приклад університету",
      "region": "Київ",
      "specialty": "121 Інженерія програмного забезпечення",
      "educationLevel": "бакалавр",
      "year": 2025,
      "womenCount": 120,
      "menCount": 210,
      "nonbinaryCount": 3
    }
  ]
}
```

- `title`: від 3 символів; `periodLabel`: від 4.
- `records`: 1–20 000; текстові поля від 2 символів; рік 2000–2100; лічильники — цілі числа 0–2 147 483 647. У JSON `nonbinaryCount` необов'язковий, типово 0; у CSV колонка й значення обов'язкові.
- Необов'язковий `apiSourceId` має посилатися на джерело тієї самої категорії.
- Необов'язковий `replaceDatasetId` запускає заміну; відсутній старий набір — 404. Можлива заміна набору з іншої категорії: перевірка однакової категорії старого й нового набору відсутня.
- Заборонено імпортувати у `site-users`, `ukraine-open-data`, `international-open-data`.
- Дублікат ключа `(institution, region, specialty, educationLevel, year)` всередині запиту — 409. Між різними наборами дедуплікації немає.

Успіх: 201 з новим `datasetId` і кількістю `imported`. GET наборів повертає `id`, `title`, `period_label`, `status`, `created_at`, `category_name`, `records_count`. Видалення набору незворотне без резервної копії.

## Помилки

Зазвичай API повертає `{ "error": "повідомлення" }` українською незалежно від мови UI.

| Код | Типові причини                                                     |
| --- | ------------------------------------------------------------------ |
| 400 | Невалідний JSON, схема, UUID, рік/число                            |
| 401 | Неправильний пароль, відсутній/прострочений/невалідний JWT         |
| 403 | Недостатня роль                                                    |
| 404 | Немає категорії/запису для оновлення/набору для заміни             |
| 409 | Унікальність, FK, дублікати рядків, заборонена категорія імпорту   |
| 413 | Перевищення розміру запиту; nginx може повернути HTML замість JSON |
| 429 | Ліміт auth-спроб; заголовок `Retry-After`                          |
| 500 | Необроблена внутрішня помилка, без SQL/stack trace клієнту         |
| 502 | Помилка зовнішнього провайдера або відсутність придатних даних     |
| 503 | Вбудований API-ресурс вимкнений або не налаштований                |

Автоматичний повтор POST імпорту небезпечний: тайм-аут клієнта не доводить, що COMMIT не відбувся.
